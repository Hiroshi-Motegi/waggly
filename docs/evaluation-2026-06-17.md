# Waggly 総合評価レポート（2026-06-17）

## 1. アプリ概要

**Waggly** (waggly.jp) は、ゴルフギア管理を軸としたゴルファー向けアプリ。Web（Next.js）+ ネイティブ（Capacitor Android/iOS）のクロスプラットフォーム構成。日本市場特化。

| DB マイグレーション | 28ファイル |
| テストファイル | 21 |
| コミット数 | 961 |
| カスタムフック | 10+ |

### アーキテクチャの強み

#### Supabase RLSによる多層防御
全テーブルRLS有効。SQLインジェクション対策もパラメータ化クエリで対応済み。

#### 認証アーキテクチャの深さ
LINE/Google/Apple対応、アカウント連携・マージ・競合解決まで実装。日本市場で必須のLINE LIFF対応。`user_providers` ジャンクションテーブルでマルチプロバイダ管理。

#### オフラインファースト設計の本格度
単純なキャッシュではなく、本格的な同期システム:
- `pending_sync` テーブルで変更キュー管理
- `sync_meta` で最終同期タイミング追跡
- `flushPendingSync()` → `fullSync()` の再接続時自動同期
- `@capacitor/network` でネットワーク状態を常時監視
- `routeLocal()` が API パスをローカル SQLite に自動ルーティング

#### ビルドシステムの工夫
Web版とネイティブ版で同じコードベースを使いながら、ビルド時に API ルートを一時退避させて Static Export を行う仕組み（`build:app` スクリプト）。

#### AI システムプロンプトの設計
`src/lib/ai/system-prompt.ts` でユーザーのクラブデータ、練習履歴、管理者が管理するナレッジベース（`knowledge_base` テーブル）をコンテキストとして注入。パーソナライズされた AI コーチングを実現。

#### セキュリティ
Pay.jp本番申請チェックリスト全5項目クリア。Webhook検証、レートリミット、3Dセキュア、Turnstile CAPTCHA。

#### パートナーシップエコシステム
計9社のサービスを統合（個人開発として異例の充実度）:
Rakuten GORA / Pay.jp / Supabase / Vercel / LINE / Google / Anthropic / A8 / Tavily

## 5. 多言語化についての評価

### 結論: 現時点ではやるべきではない

#### やらない理由

**1. 日本市場特化がそのまま競争優位**

Wagglyの強みは日本市場への深い最適化:
- LINE認証（海外では意味なし）
- 楽天GORA連携（日本のみ）
- Pay.jp（日本のみ）
- LIFF対応（LINEユーザー前提）

多言語化するとこれらを全て代替する必要があり、翻訳ではなく別プロダクトを作るに近い工数になる。

**2. 日本市場をまだ取りきっていない**

ボトルネックは「多言語じゃないから伸びない」ではなく:
- アプリストア未公開（発見性ゼロ）
- SEO弱い（オーガニック流入ほぼなし）
- リテンション施策なし（Push通知ゼロ）

日本のゴルファー560万人中、SAM 10-30万人に対して現ユーザーはまだごく少数。日本市場だけで10-100倍の伸びしろがある。

**3. 海外ゴルフアプリ市場は激戦**

英語圏の競合:
- Arccos（$200/年、スマートセンサー連動）
- Shot Scope（ハードウェア付き）
- 18Birdies（500万DL、スコア+GPS）
- Golfshot（老舗、GPS中心）
- WITB.golf（ギア特化SNS）

日本市場でギア管理×AI×LINE連携は実質的に競合ゼロだが、海外では資金力で圧倒的な差がある。

#### やる価値がある条件

| 条件 | 現状 |
|------|------|
| 日本で月間Pro 5,000人超 | 未達 |
| アプリストア公開済み・評価4.0以上 | 未公開 |
| SEOで「ゴルフ ギア管理」1ページ目 | 未達 |
| リテンション率30日 > 40% | 計測不可 |
| 開発リソースに余裕がある | 個人開発 |

#### 将来やるなら段階的に

```
Phase 0（今）: やらない。日本で勝つ
     ↓
Phase 1: クラブカタログページだけ英語対応
  - club_specsのスペック情報は元々英語（メーカー名・モデル名）
  - SEO流入目的の静的ページなので低コスト
  - 海外需要のテストマーケティングになる
     ↓
Phase 2: 反応があれば、コア機能の英語UI
  - next-intl等でi18n基盤構築
  - Stripe移行（Pay.jpと並行運用）
  - Google/Apple認証のみ（LINE不要）
     ↓
Phase 3: 本格展開
  - 海外ゴルフ場API連携
  - 英語ナレッジベース
  - 現地通貨対応
```

## 総括

最大のボトルネックは「作ったものが見つけてもらえない」（SEO/アプリストア）と「使い続ける理由が弱い」（リテンション）の2点。技術的には十分整っているので、マーケティング施策の実行がスケールの鍵。

日本市場でギア管理のカテゴリリーダーになるポテンシャルは十分にある。多言語化は日本で確固たるポジションを取ってから。
