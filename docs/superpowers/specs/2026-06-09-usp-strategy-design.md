## 1. ポジショニング

### コンセプト（更新）

旧: 「自分のクラブセットを管理し、練習日記とAIで上達をサポートする、ゴルファーの道具手帳」

**新: 「ギアに本気なゴルファーのためのプラットフォーム — 業界最高のギア管理体験を軸に、練習のきっかけを作り、本気の改善は餅屋に繋ぐ」**

### 一言USP

> 「自分のギアを、ここまで管理できるアプリは他にない」— ギア特化型ゴルフプラットフォーム

### Wagglyの3層構造

| 層 | 領域 | ユーザー体験 | 裏側のロジック | 限界 |
|---|---|---|---|---|
| **コア** | ギア管理 | **本気** — 業界最高のギア管理体験 | 本気 | — |
| **サブ** | 練習記録 | **ライト** — タグをポチポチ選ぶだけ | **本気** — 構造化データ × ビッグデータ × AI で統計的知見を蓄積・提示 | 統計・一般論止まり。個別診断はしない |
| **橋渡し** | スコア改善 | **餅屋に任せる** | アフィリエイト送客 | — |

#### サブ層のデータフライホイール

```
ユーザーが構造化メモを記録（ライトな体験）
  ↓
匿名データとして集約（N人分の傾向）
  ↓
ナレッジ自動収集パイプライン（既存）でPDCA
  - Claude分析: 多い症状パターン・未カバーのトピックを特定
  - Tavily検索: 最新のゴルフ知見を収集
  - Claude生成: 教師データとしてナレッジベースに蓄積
  ↓
ユーザーへの還元
  - 症状タグ選択時に「一般的な原因」を参考表示
  - AIチャットの応答精度向上
  - クラブ詳細画面の傾向分析
  ↓
ユーザーが増える → データが増える → ナレッジが改善される（好循環）
```

#### AIの立ち位置: 診断ではなく統計情報の提示

| | Waggly（ビッグデータ × AI） | レッスンプロ |
|---|---|---|
| **強み** | N人分の匿名データから傾向を提示。24時間・無料〜安価 | 目の前のあなたのスイングを見て原因特定 |
| **弱み** | 個別のスイングは見えない。「右に出る人は一般的に〜」止まり | 高い・予約制・1対1 |
| **役割** | 気づきを与える。「こういう傾向あるよ」 | 解決する。「あなたの場合はこれ」 |

練習場で一人で悩んでいるときに、ヒントがあるだけで違う。それでも解決しないなら「プロに見てもらいましょう」→ 送客。ビッグデータ × AIの強みが活きるのは「個別解」ではなく「N人の傾向から見える統計的知見」。ユーザーが増えるほどこの価値は上がる。

ギアは嗜好品。スコアは実力。この2つは別軸。
高いクラブを持っていても下手ならダサい — だからこそ「ギアを愛でる」と「練習するきっかけ」を両方提供し、本気ゾーンには送客する。

### 市場ポジション

Wagglyは「点」のサービス同士をつなぐ「線」— 隙間のソリューション。

| | ギア管理が浅い | ギア管理が深い |
|---|---|---|
| **AI/知的提案あり** | (空白) | **Waggly** |
| **AI/知的提案なし** | 楽天GORA, GDO | ギアマネ |

ゴルフアプリ市場の成熟度:
- コース予約、スコア管理 → **飽和（レッドオーシャン）**
- スイング分析 → **成長中（AI参入激化）**
- ギア管理 + シェア → **未開拓（ブルーオーシャン）。本気プレイヤー不在**

「ギアを管理したい人」はニッチだが、「ギアを自慢・共有したい人」はゴルファー全体。管理は手段、自慢とシェアが目的。管理機能は「自慢するための舞台裏」として自然に使われる。

### 競合との関係

- **vs ギアマネ**: 管理ツール止まり。ギアへの愛着・自慢・シェアの感情を拾えていない
- **vs スコアアプリ**: スコアは他所に任せる。ギアとその周辺に集中
- **vs レッスン/スイング分析**: 競合しない。補完関係。送客先

### カーチューン的世界観

自動車のカーチューンのように、ゴルファーが自分のギアを記録・管理・シェアするプラットフォーム。ただし現時点ではゴルフ業界にこの決定版が存在しない（ギアマネは管理ツール止まり、ゴルフSNS系はギアの深掘りがない）。

参考: カーチューンは自動車保有者6,000万人中MAU 20万人（0.3%）。ゴルファー480〜912万人に同率を当てはめると1.5〜2.7万人が理論上限だが、ギア消費行動（ドライバー買い替え2年に1回が51%、年間ギア予算5〜20万円）を考えると、熱量の高いユーザー層にリーチできればLTVで勝負できる。

## 2. 戦略アプローチ: ギアファースト戦略

ギア管理で業界最高の体験を作る → 知り合いに自慢 → コミュニティ化 → 収益化。

### 成長ステップ

```
① ギアを本気で管理（クラブ + ラウンドする一切のギア）
  ↓ 使い続ける理由を作る
② 知り合いに自慢（クローズドシェア）
  ↓ バイラル装置
③ 多数に自慢 + 相談（オープンコミュニティ化）
  ↓ ネットワーク効果
④ 収益化（アフィリエイト + 課金 + 外部連携）
```

### フェーズ構成

| Phase | 内容 | 目的 |
|-------|------|------|
| **Phase 1** | クラブ管理強化 + 全ギア管理拡張 + 構造化メモ | 使い続ける理由を作る |
| **Phase 2** | ゴルファーカード + クローズドシェア（知り合いに自慢） | バイラル装置 |
| **Phase 3** | オープンコミュニティ化（多数に自慢 + 相談） | ネットワーク効果 |
| **Phase 4** | 収益化（アフィリエイト + 課金）+ 外部連携 | マネタイズ |

#### 全ギア管理の対象（Phase 1）

既存の `accessories` テーブル（category: ball/glove/tee/other）のカテゴリを拡張:

| カテゴリ | 現状 | Phase 1 |
|---------|------|---------|
| クラブ | clubs テーブルで実装済み | 管理強化（WITBビジュアル、飛距離階段、重量フロー） |
| ボール / グローブ / ティー | accessories テーブルで実装済み | そのまま活用 |
| シューズ / キャディバッグ / レンジファインダー / ウェア / サングラス / 小物 | 未対応 | accessories テーブルの category 追加で対応 |

### 収益モデル

- **フリーミアム**: 基本無料 / AI相談・プレミアム分析は月額課金
- **将来的にアフィリエイト**: クラブ売買・買い替え時のEC送客、ゴルフスクール送客、買取査定送客
- 構造化メモにより悩みデータが蓄積されるため、適切なタイミングで適切な送客が可能（高コンバージョン率が期待できる）

## 3. Phase 1 機能セット

### 3.1 ギア管理強化（ギアマネ踏襲+α）

| 機能 | 現状 | Phase 1 |
|------|------|---------|
| WITBビジュアル | リスト表示のみ | カード型ビジュアル + SNSシェア画像生成 |
| 飛距離階段グラフ | ギャップ分析（テキスト） | ビジュアルグラフ化 + ギャップ可視化 |
| 重量フロー | なし | クラブ重量の流れを可視化 |
| メンテ履歴 | あり | そのまま活用 |
| ライフサイクル | status(bag/reserve/sold)あり | タイムライン表示 |

### 3.2 練習記録のギア起点化

現在の練習記録は「セッション起点」（6/8に120球打った）。これを「ギア起点」に再定義する。

**Before（セッション起点）:**
- 6/8 練習 120球 → 7I: 40球 / PW: 30球 / Dr: 50球

**After（ギア起点）:**
- 7I（PING i230）→ 直近30日: 計180球 / メモ:「右に出る」「シャフト硬いかも」/ 平均飛距離推移

クラブ詳細画面に「使用サマリー」「よく出るキーワード」「直近メモ」が並び、メモが溜まるほどクラブのプロフィールが育つ。

### 3.3 構造化メモUI

ユーザーは気軽にメモしているだけなのに、蓄積すると「このクラブの傾向」が見える設計。

#### 設計原則

- **入力できるもの（自分でわかること）だけ入力させる**
- スイングの技術的な原因（捻転不足、クロス等）は自分では見えない。プロの領域なので入力させない
- 症状に応じた一般的な原因リストはナレッジベースから参考表示（読むだけ）

#### 入力構造

**悩み時:**

1. クラブ選択（自分のバッグから）
2. 調子（😣悩み / 😐普通 / 😊好調）
3. 症状タグ（複数選択OK）
   - 球筋: 右に出る / 左に出る / スライス / フック / バラつく
   - 弾道: 高すぎ / 低すぎ / 吹き上がる / ドロップ
   - ミス: トップ / ダフリ / シャンク / テンプラ / 飛距離不足
4. 体の感覚タグ: 力んだ / 芯に当たらない / リズム悪い / 疲れ / 振り切れない / 手打ち感
5. ギアの気づきタグ: 硬い / 柔い / 重い / 軽い / グリップ滑る / 構えにくい
6. 自由メモ（任意）
7. 参考表示: 症状に応じた一般的な原因リスト（ナレッジベースから。読むだけ）

**好調時:**

1. クラブ選択
2. 調子（😊好調）
3. 何が良かった？タグ: 距離感 / 方向性 / 打感 / 高さ / 安定性 / スピン
4. 自由メモ（任意）

※ タグの具体的な項目は実装フェーズで詳細設計する。

#### 蓄積後の表示（クラブ詳細画面）

- 使用サマリー: 総打球数 / 平均飛距離 / 悩みメモ回数
- 症状の傾向: バーチャートで「右に出る ×4」等を可視化
- よく出るキーワード: タグの出現頻度
- 直近のメモ: 時系列で調子アイコン + タグ + 自由メモ

#### 将来的な収益導線（Phase 3以降）

構造化メモにより悩みが構造化されて蓄積されるため、適切なタイミングで送客が可能:
- 症状メモ蓄積 → ゴルフスクールアフィリエイト（5,000〜50,000円/件）
- ギアへの疑問蓄積 → EC送客アフィリエイト
- 売却ステータス変更 → 買取査定アフィリエイト

### 3.4 ギャップ可視化

既存のルールベースギャップ分析（隣接クラブ間の飛距離差 >20yd を検出）を、テキスト表示からビジュアルグラフに強化する。AIによる提案は行わない。

### 3.5 AIチャット

既存のまま維持。聞かれたら答える。押し売りしない。

## 4. Phase 2: ゴルファーカード + シェア

> 詳細設計は `2026-06-09-golfer-card-design.md` を参照。以下は要約と戦略的位置づけ。

### 目的

バイラル装置。ゴルフ場で隣の人に「見て」と見せる → 即登録の導線。

### 機能概要

- **プロフィール設定**: ニックネーム、ゴルフ歴、平均/ベストスコア、ホームコース、ひとこと、SNSリンク
- **公開ページ** (`/p/[username]`): セッティング一覧 + プロフィール。ログイン不要で閲覧可能
- **シェアフロー**: URLコピー + QRコード生成。名刺交換的にライトにシェア
- **お気に入りコース**: 楽天GORA連携 + 手動入力
- **公開/非公開制御**: 項目ごとに公開/非公開を設定可能

### データモデル

- `profiles` テーブル（新規）: username, nickname, avatar_url, golf_experience_years, average_score, best_score, home_course, bio, sns_links, is_public, visible_fields
- `favorite_courses` テーブル（新規）: gora_course_id, course_name, course_image_url, evaluation, is_manual, sort_order

### LINEとの相性

LIFFアプリ内でシェアできるため、LINE友達への展開が自然。

## 5. Phase 3: AIギア相談 + 収益化 + 外部連携

### AIギア相談

既存のAIチャット・練習提案の仕組みをギア方向に拡張。ただし精度が担保できない提案（買い替え提案、セッティング診断）は行わない。

- **メモ×履歴の振り返り**: 構造化メモの蓄積から「7Iで右に出る記録が3回」等のパターンを提示
- **練習メニュー**: 既存機能をギア起点（「このクラブをもっと活かす」視点）に再構成
- **ナレッジベース活用**: 自動収集パイプライン（`2026-06-08-knowledge-auto-collect-design.md`）で蓄積した教師データを、症状への参考表示やチャット応答に活用

### 収益化

#### フリーミアム課金

- 基本無料 / AI相談・プレミアム分析は月額課金
- 既存のStripe課金設計（AIトークン上限）を活用

#### アフィリエイト

構造化メモにより悩みデータが構造化・蓄積されるため、適切なタイミングで適切な送客が可能:

| 送客先 | 報酬相場 | 導線 |
|--------|---------|------|
| ゴルフスクール入会 | 5,000〜50,000円/件 | 症状メモ蓄積 →「プロに見てもらいませんか？」 |
| ゴルフ用品EC（GDO等） | 購入額の数% | ギアへの疑問蓄積 → 買い替え検討時に送客 |
| ゴルフ用品買取 | 1,000〜3,000円/件 | 売却ステータス変更 →「買い取り査定どうですか？」 |

### 外部連携

APIがあれば積極的に連携:
- トラックマン / Garmin（計測データの自動取り込み）
- 楽天GORA（コース情報。Phase 2で一部実装済み）
- Arccos（ショットデータ。On-Course Data API）

## 6. やらないこと

- **スコア管理**: 楽天GORAやGDOで既に記録している。転記は誰もやらない
- **スイング分析**: 餅は餅屋。補完関係
- **AIによる買い替え提案**: 精度が担保できない。信頼を落とすリスク
- **AIによるセッティング診断**: 同上
- **スイング原因の入力**: ユーザーには見えない情報（捻転不足、クロス等）。プロの領域
- **オープンなSNSタイムライン**: Phase 2でもクローズド（URL/QR知っている人のみ）

## 7. 技術的な注意事項

### Phase 1

- 構造化メモのタグは DB に enum またはマスターテーブルとして持つ（将来的なタグ追加・分析のため）
- クラブ詳細画面のサマリーはクライアントサイド集計で十分（初期はデータ量が少ない）
- WITBビジュアル・飛距離階段・重量フローはチャートライブラリ（recharts等）で実装
- SNSシェア画像生成は canvas API or サーバーサイドレンダリング（OGP対応も考慮）

### Phase 2

- `profiles` / `favorite_courses` テーブル追加（詳細は golfer-card-design.md）
- QRコード生成はクライアントサイド（`qrcode` ライブラリ等）
- 公開ページは非ログインでも閲覧可能（Supabase RLSで `is_public: true` のみ読み取り許可）
- OGP動的生成（LINE等でシェア時にプレビュー表示）

### Phase 3

- ナレッジ自動収集パイプライン（詳細は knowledge-auto-collect-design.md）をそのまま活用
- 構造化メモの症状タグとナレッジベースの紐付けロジック追加
- アフィリエイトリンクの管理テーブル追加（送客先、報酬条件、表示条件）
- 外部API連携は個別に調査・設計（APIの利用可否・コスト・認証方式）
